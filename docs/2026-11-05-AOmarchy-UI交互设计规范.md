# AOmarchy UI / 交互设计规范

日期：2026-11-05 ・ 适用范围：`app.aomarchy` 控制台、启动页、桌面小组件、通知与快捷方式

---

## 0. 现状诊断

| 位置 | 问题 | 影响 |
|---|---|---|
| 全局 | 启动页用 `#9CD462` 草绿 + CRT 复古终端，App 内用 `#7C8CFF` 靛蓝玻璃控制台 | 品牌割裂，进入 App 时像换了产品 |
| 概览页 | 「进入桌面」与「运行中」在顶栏、会话卡各出现一次 | 同屏两个主 CTA、两个状态源，用户不确定点哪个 |
| 概览页 | 六张指标卡（CPU / 内存 / 磁盘 / 电量 / 网络 / GPU）视觉权重完全相同 | 没有主次，扫读成本高 |
| 概览页 | 内容只占上半屏，右下约 1/3 空白 | 信息密度不足，平板横屏浪费 |
| 导航栏 | 系统＝太阳、应用＝点阵、设置＝太阳，图标语义抽象且重复 | 靠文字标签才能辨认，图标失效 |
| 玻璃层 | 取色依赖底图；纯色模式回退到靛蓝，亮底图下轻 scrim 让文字对比浮动 | 可读性随用户壁纸变化，不可控 |
| 颜色语义 | 薄荷 `#5FE1B4` 与信号绿 `#9CD462` 同时承担「运行中」 | 两套绿互相打架 |

现状约束：UI 由 framework views 纯 Java 手绘、无 androidx、固定深色主题（刻意独立于桌面 Omarchy 主题）、平板横屏左侧 rail / 手机竖屏底栏。本规范只改设计层，不改变技术栈。

## 1. 设计基础

### 1.1 色彩系统 —— 双色融合

**角色定义（最重要的规则）**
- **Indigo 靛蓝 = 结构色**：主操作、选中态、焦点、导航、图形骨架。它是这个品牌的"脸"。
- **Signal Green 信号绿 = 状态色**：仅限「运行中 / 就绪 / 成功 / 已完成」。不得用作主按钮或大面积背景。
- **Mint 薄荷 = 终端模式专用**：仅用于区分「终端」这一启动方式，不参与通用状态表达。
- 禁止用颜色单独传达状态，必须同时有文案 + 图标。

| 阶 | Indigo（结构） | Signal Green（状态） | 用途 |
|---|---|---|---|
| 50 | `#EEF0FF` | `#F0FBE4` | 亮色模式底 / 极浅填充 |
| 100 | `#D8DDFF` | `#DDF5C2` | 浅填充、禁用态 |
| 200 | `#B4BEFF` | `#BDEB92` | 弱化描边、图表次级 |
| 300 | `#9AA8FF` | `#9CD462` | 焦点环、信号绿基准（沿用启动页绿） |
| 400 | `#7C8CFF` | `#7FBB48` | **主色**（沿用现有 ACCENT）/ 绿深态 |
| 500 | `#6172F0` | `#639A34` | hover / 按下 |
| 600 | `#4C5BD4` | `#4B7826` | pressed |
| 700 | `#3B47A8` | `#38591C` | 文字化主色（浅底） |
| 800 | `#2A3277` | `#263D13` | 深表面 |
| 900 | `#1A1F4A` | `#17260B` | 最深表面 |

**中性色**（沿用，不改）

| Token | 值 | 用途 |
|---|---|---|
| `BG` | `#0A0C10` | 页面底 |
| `SURFACE` | `#14171F` | 卡片 / 小组件 |
| `SURFACE_HI` | `#1C2230` | 卡片内分层 |
| `LINE` | `#262C3A` | 分隔线 |
| `TEXT` | `#E6E9F0` | 主文 |
| `DIM` | `#A8B3C4` | 次文 |
| `FAINT` | `#5C6675` | 仅装饰 / 禁用态 |

**语义色**：`WARN #FF6B6B`（错误 / 危险）、`WARN_BG #3A1A1E`（错误容器）、`INFO = Indigo 300`。

**对比度实测（WCAG 2.2 AA，深色底 `#0A0C10`）**

| 前景 | 对比度 | 结论 |
|---|---|---|
| `TEXT #E6E9F0` | ≈ 16.0:1 | 正文通过 |
| `DIM #A8B3C4` | ≈ 9.2:1 | 正文通过 |
| `Indigo 400 #7C8CFF` | ≈ 6.5:1 | 正文与 UI 组件均通过 |
| `Signal 300 #9CD462` | ≈ 11.1:1 | 正文通过 |
| `WARN #FF6B6B` | ≈ 6.0:1 | 正文通过 |
| `FAINT #5C6675` | ≈ **3.4:1** | **不达标**：不得用于正文，仅限装饰 / 禁用；需承载文字时提亮到 `#7A8595`（≈ 5.2:1） |

> 需复核：`LINE #262C3A` 对 `BG` 仅约 1.4:1。若某处边框是识别组件边界的唯一手段，必须换成 `GLASS_LINE`（白色半透明发丝线，≥ 3:1）或提亮到 `#3A4356`。

### 1.2 字体刻度（8px 基线）

两套字体上限：界面用系统无衬线（中文由 rootfs 的 Noto Sans CJK 对齐桌面），数据与代码用等宽（JetBrains Mono 观感）。

| Token | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| `display` | 32 / 40 | 700 | 页面主数值、欢迎标题 |
| `headline-lg` | 26 / 32 | 700 | 页面标题 |
| `headline-md` | 22 / 28 | 600 | 卡片标题 |
| `headline-sm` | 18 / 24 | 600 | 分区标题 |
| `body-lg` | 16 / 24 | 400 | 主要说明 |
| `body-md` | 14 / 20 | 400 | 正文 |
| `body-sm` | 12 / 16 | 400 | 辅助说明 |
| `label-md` | 12 / 16 · 0.05em | 600 | 卡片标签、按钮 |
| `label-sm` | 10 / 14 · 0.08em | 600 | 全大写小标 |
| `metric` | 32 / 40 · 等宽 | 500 | 指标数值 |

### 1.3 间距与圆角

间距一律 8 的倍数：`4 / 8 / 12 / 16 / 24 / 32 / 48`。卡片内边距 16，卡片间距 16，栅格 gutter 24（平板）/ 16（手机）。
圆角层级：元素 8 → 卡片 16 → rail 22 → 胶囊 full。层级不能倒挂。

### 1.4 断点（移动优先）

| 断点 | 形态 |
|---|---|
| ≥ 320px | 单列，底栏 5 tab，触控目标 ≥ 48dp |
| ≥ 576px | 卡片两列，指标卡保持单列 |
| ≥ 768px | 左侧 rail（宽 72dp）+ 内容 12 栅格，指标卡两列 |
| ≥ 992px | 内容区最大宽 1120dp，概览可分主区 + 侧区 |
| ≥ 1200px | 概览使用 2+4 指标布局与下半屏信息区 |

## 2. 布局

**平板横屏**：rail 固定 72dp（图标 24dp + 10dp 标签），内容区左右 24dp 边距，12 栅格。顶栏只放品牌名 + 唯一状态 + 唯一主 CTA。

**概览页改后结构**

```
顶栏    AOmarchy            [● 运行中]  [进入桌面]   ← 唯一状态、唯一主 CTA
主区    会话卡（运行时长 / 会话类型 / 次操作：安装·重装、挂起、停止）
        ┌ 主指标：CPU（大数值 + sparkline） ┐┌ 主指标：内存（大数值 + 占比条）┐
        └ 紧凑行：磁盘 · 电量 · 网络 · GPU（4 行，标签左 / 值右）┘
下半区  智能建议（左）        最近备份 / 更新状态（右）
```

**竖屏**：底栏 5 tab，顶栏折叠为品牌名 + 主 CTA，状态胶囊并入会话卡。

## 3. 组件清单与状态

| 组件 | 必状态 | 视觉要点 |
|---|---|---|
| 主按钮 | default / hover / pressed / focus / loading / disabled | Indigo 400 实底 + `#0A0C10` 文字；全页每屏至多 1 个 |
| 次按钮 | 同上 | `SURFACE_HI` 底 + `GLASS_LINE` 描边 |
| 状态胶囊 | ready / running / terminal / stopped / error | 色点 + 图标 + 文案三件套；禁止只用颜色 |
| 指标卡（主） | normal / warning / loading | 32px 等宽数值、单位降权、趋势线为装饰且跳过读屏 |
| 指标行（次） | normal / warning | 14px 标签左、16px 等宽值右，一行解决 |
| rail / 底栏项 | default / selected / focus | 选中＝Indigo 400 图标 + 2dp 指示条；指示条动效只动 transform |
| 卡片 | normal / empty / error | 16px 圆角、发丝线、纯色模式下不依赖底图取色 |
| 进度条 | determinate / indeterminate / success / error | 高度 6dp，success 用 Signal 300，error 用 WARN |
| Toast | info / success / error | 底部 16dp，4 秒自动消失，不遮挡主 CTA |
| 空态 | 未安装 / 无备份 / 日志为空 / 无网络 | 统一：图标 + 一句说明 + 一个次按钮 |

**微交互参数**（克制原则）

| 动作 | 参数 |
|---|---|
| hover | `scale(1.05)`，0.2s `ease-out` |
| pressed | `scale(0.95)`，0.15s `ease-in` |
| 页面切换 | fade 0.2s + 8dp 横向位移，0.25s |
| rail 指示条 / 数字滚动 | 0.3s 弹簧，`transform` / `opacity` only |
| 焦点 | 2dp `Indigo 300` 环 + 2dp offset，键盘操作时常显 |
| 全局 | 尊重系统「移除动画」；禁止动画 `width` / `height` / `background-color` |

## 4. 交互改进清单

**P0（建议本轮先改）**

1. **合并重复主 CTA**：顶栏「进入桌面」保留为唯一主按钮；会话卡内改为「安装 / 重装系统」「挂起 / 停止」等次操作，不再出现第二个「进入桌面」。
2. **合并重复状态**：顶栏状态胶囊作为唯一状态源；会话卡右上角状态胶囊删除，改为显示运行时长 + 会话类型（桌面 / 终端）。
3. **建立指标主次**：CPU、内存升为主卡（32px 等宽数值 + 趋势/占比），磁盘、电量、网络、GPU 降为紧凑行。六卡平铺改为 2 主 + 4 行。
4. **填补下半屏**：概览下部放「智能建议」与「最近备份 / 更新状态」两栏；已上线的智能建议卡提升到这一层并常驻。
5. **重绘 rail 图标**：概览＝四宫格瓦片、系统＝芯片 / 硬盘、应用＝应用方格、控制＝滑杆、设置＝齿轮。取消两处太阳图标，一个图标只对应一个语义。
6. **玻璃层可读性兜底**：底图取色结果需过一层最小 scrim（建议 ≥ 55% 深色），保证 `TEXT` 在任意壁纸上不低于 4.5:1；纯色模式统一回退到 `Indigo 400` 低强度，不要出现"亮底图 + 轻 scrim"的组合。

**P1（随后跟进）**

7. 状态不只靠颜色：运行中＝绿点 + 「运行中」+ 播放图标；错误同理。
8. 键盘导航顺序：rail → 顶栏 → 内容区，焦点环常显（见微交互表）。
9. 触控目标保持 ≥ 48dp，TalkBack 描述包含当前值 / 开关状态；sparkline、进度条、分隔线等装饰视图跳过读屏。
10. 空态四态统一文案与图示，避免「一片空白」。
11. 启动页 / 首次启动页换色到 Indigo 400，移除 CRT 扫描线与闪烁（flicker 对光敏感用户不友好）；进度条用 Indigo，完成态才用 Signal 300。
12. 「进入桌面」按钮在会话已运行时改为「返回桌面」，避免「再进一次」的歧义。

## 8. 落地状态（2026-11-05 更新）

实际落地清单、真机验收与遗留项见 `docs/2026-11-05-AOmarchy-品牌落地说明.md`。两处需要说明：

- **对 §2 的一处刻意偏离**：规范写「顶栏放唯一主 CTA」，实现时改为「概览页主 CTA 放在 hero 卡内，顶栏按钮在概览页隐藏、其他 4 个页面保留为返回会话的全局入口」。原因是顶栏按钮是跨页面快捷入口，全删会让系统 / 应用 / 设置页失去一键进入会话；而概览页若两个都留，就是真机截图里那对重复的「进入终端」。这样既保证每屏只有一个主 CTA，也不丢功能。
- **P0-3「建立指标主次」暂未落地**：四张指标卡仍等权。这是信息架构重排，涉及 `OverviewPage` 布局与 `poll()` 更新逻辑，建议基于真机观感再决策，不要为对齐这份基于旧截图的诊断而盲改。
