## 9. 启动方式切换的状态检测与重启询问（第四轮）

用户要求：切换时检测系统状态及正在运行的方式，提示并询问是否需要重启系统。

**运行态判定看实际，不看偏好**：新增 `SessionService.runningMode(Context)`，返回 `none` / `stopped` / `desktop` / `terminal`：

| 值 | 判定依据 |
| --- | --- |
| `none` | `rootfsReady` 为 false（系统未安装） |
| `terminal` | `TerminalActivity.sRunning`（新增静态标记，onCreate / onDestroy 维护） |
| `desktop` | `SessionService.started`（桌面合成器服务在跑） |
| `stopped` | 已安装但无活动会话 |

`session_mode` 只是「下次启动的计划」，与「正在运行的方式」被明确区分开。

**切换流程**（`ShellActivity.pickStartupMode`）：

- 选到与当前相同的值 → 直接返回，不改动。
- `none` / `stopped` → `applyStartupMode()` 保存并同步顶栏、主按钮、桌面小组件、当前页；toast 说明「系统未安装，安装后生效」或「Linux 未运行，下次启动生效」，不打扰用户。
- `desktop` / `terminal` → 弹确认框：标题「切换启动方式需要重启 Linux？」，正文写明「当前正以 X 运行 → 切换到 Y」，并警告重启会断开运行中的桌面或终端、需先保存工作；三个按钮「立即重启」/「取消」/「下次生效」。
  - **立即重启**：保存后 `restartSessionForMode()` —— 停止 `SessionService`，提示「正在重启 Linux…」，700 ms 后调用 `openDesktop()` 按新偏好重新进入（桌面＝启动服务 + 桌面界面；终端＝直接开 pty，不起服务）。
  - **下次生效**：只保存，不重启。
  - **取消**：不保存、不重启。
- `T.java` 新增 6 个中英双语文案。注意 `T.t(key, args)` 是顺序替换字面 `%s`，**不支持** `%1$s` 这类定位占位符。

**真机验证**：

- 未运行：从「终端（省资源）」切到「完整桌面」，顶栏与主按钮立即更新，toast「Linux 未运行，已设为「完整桌面」，下次启动生效」，没有多此一举的询问框。
- 运行中：启动 Linux 会话（状态「● 运行中」、已运行 0 分 8 秒、43 个进程）后切回终端，弹出询问框并正确显示「完整桌面 → 终端（省资源）」。
- 验证后点「取消」、停止会话、把模式恢复为原来的「终端（省资源）」，状态回到「就绪」，设备偏好未被改变。截图见 `2026-11-05-AOmarchy-真机验收-启动方式切换.png`。

## 11. 玻璃美学重做（第六轮，推倒重来）

用户对原卡片观感不满意（「之前用的模型不好」），提供两张光学参考图（深色玻璃面板 + 浅底大透明玻璃），要求实现「真正的玻璃美学」。核心判定：玻璃 = **背景真模糊 + 通透面板 + 微亮边缘 + 轻柔阴影**，缺一不可。

### 落地结构

- **`CardBackground.java` 整体重写**（所有玻璃面板的视觉本体）：垂直厚度渐变填充（顶部 lighten 5.5%）、顶部内侧高光带（22% 高度 / 最多 26dp）、双层 bevel 漫射环、斜向 sheen、GlassTint 环境光 wash、按压 glint + squash 回弹、渐变边框。
- **`Ui.java`**：`Ui.surface()` / `Ui.rail()` 返回类型改为 `Drawable`，内部改用 `CardBackground` —— rail、所有 pill/cell/panel 与卡片统一为同一套玻璃绘制；卡片圆角 22→24、elevation 8→12；次按钮底色大幅减淡。
- **`Wallpaper.java`**：背景开启真实 RenderEffect 模糊；scrim 大幅降低。
- 玻璃常量：`GLASS = 0x33101622`（卡片 20%）、`GLASS_STRONG = 0x4710151F`（rail/pill 28%）。

| 轮 | 调整 | 真机结果 |
